# /save-prompt

## 目的
依頼文（原文）と作業結果を、あとから読んで再現できる形で `docs/prompt/` に残し、すべての変更を `main` に反映する。

## いつ実行するか
- `/save-prompt` と言われたとき。
- 言われなくても、**依頼が終わるたびに毎回自動で**実行する（ルートの `CLAUDE.md` に記載）。
- 質問への回答だけでファイルを変更しなかった依頼も、同じ日の一連の流れの記録に追記する。

## 手順
1. **日付**は Asia/Tokyo の現地日付を使う（`TZ=Asia/Tokyo date +%y%m%d`）。
2. **ファイル名**は `docs/prompt/YYMMDD-題名.md`。同じ日に、別の流れの記録が複数必要なときは `YYMMDD-01-題名.md`、`YYMMDD-02-題名.md` のように連番をつける。
3. **同じ日の記録をまとめる**：その日付の `docs/prompt/` のファイルを先に確認し、一連の流れでまとめられる内容なら、新しいファイルを作らずに既存のファイルへ追記する。同じプロンプトを二重に保存しない。
4. **プロンプト本文**：`## プロンプト本文（原文）` の下に、ユーザーのプロンプトを**そのまま**書き写す。言い換え・要約・句読点や誤字の修正をしない。過去のやり取りを補って「原文」としない。追加のプロンプトは `## 追加プロンプト（原文）` として、順番どおりに残す。
5. **結果のまとめ**：各プロンプトの直後の `## 実行結果` に、行ったこと、変更したファイル、確認したこと、残りの作業、エラーを書く。実施したことと、予定・提案にとどまることを区別し、確かめていないことを成功と書かない。
6. **一覧の更新**：新しい記録ファイルを作ったら、`docs/prompt/README.md` の一覧表（新しい日付が上）に追加する。一覧がなければ作る。
7. リポジトリに `tools/html_to_md.py` があり、`docs/` の HTML ページを変更したときは、`python3 tools/html_to_md.py` を実行して `docs/md/` の写しを同じ内容に保つ。
8. **コミット前の確認**：`git status` と `git diff` を見る。秘密情報・認証情報・子どもを特定できる情報（子どもの作文、名前、学校に関する情報など）・無関係なファイルが含まれていないことを確認する。
9. **すべての変更を git add してコミット**：`git add -A` で、それまでのすべての変更をステージし、内容の分かるメッセージでコミットする。
10. **main に push**：
    - `git fetch origin main` で最新の `main` を取得し、作業ブランチにいる場合は `origin/main` をマージしてから進める。衝突したら、両方の変更を残す形で解消する。解消できないときは止めて、ユーザーに確認する。
    - `main` にいるときは `git push origin main`、作業ブランチにいるときは作業ブランチを push したうえで `git push origin HEAD:main` で `main` にも反映する。
    - force push はしない。ネットワークエラーのときだけ、2秒・4秒・8秒・16秒の間隔で最大4回やり直す。
11. GitHub API でファイルを直接書いた場合は、それ自体が `main` へのコミットになる。ローカルで `git add` や `git push` をしたとは書かない。
12. **複数のリポジトリにまたがる作業**：変更したリポジトリごとに、そのリポジトリの `docs/prompt/` に記録してコミット・push する（公開リポジトリは下の例外に従う）。
13. **報告**：記録したファイル、push したコミットの SHA、できなかったこと（push が拒否された、など）をユーザーに伝える。

## このリポジトリでの例外（公開リポジトリ）
このリポジトリは公開されているため、**作業記録（`docs/prompt/`）をこのリポジトリには置かない**（依頼文に、非公開にしておくべき情報が含まれることがあるため）。

- 記録は、非公開の作業用リポジトリ `writing-presentation-lab` の `docs/prompt/` に、上の手順2〜6で保存する。題名に、このリポジトリの作業であることが分かる言葉を入れる（例：`261030-english-writing-lab-土台.md`）。
- `writing-presentation-lab` が手元にない場合は、GitHub 連携で `writing-presentation-lab` の `main` に直接書く。どちらもできない場合は、記録できなかったことをユーザーに伝える。
- このリポジトリの変更は、手順8〜10のとおり `git add -A` してコミットし、`main` に push する。push の前に、作業記録・子どもの情報・非公開リポジトリへのリンクが入っていないことを確認する。
